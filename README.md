# BBDown Web

基于 [BBDown](https://github.com/nilaoda/BBDown) 的可视化 Web 封装，零依赖，纯 PowerShell 驱动。

## 致谢

本项目仅为 [nilaoda/BBDown](https://github.com/nilaoda/BBDown) 的图形化前端封装，核心下载功能完全由 BBDown 提供。感谢原作者及相关贡献者的开发与维护。

## 快速开始

1. 确保目录下包含 `BBDown.exe`、`ffmpeg.exe`、`server.ps1`、`index.html`、`login-worker.ps1`、`qrcode.min.js`
2. 双击 `启动.bat`
3. 浏览器自动打开 `http://localhost:3000`

## 功能说明

### 登录

点击"扫码登录"：自研扫码流程（`login-worker.ps1` + `qrcode.min.js`），绕过 BBDown 1.6.3 的"假登录"bug，从 Set-Cookie 提取 SESSDATA。

登录后可下载高画质视频。登录态保存在 `BBDown.data` 文件中。

> ⚠️ **已知问题**：BBDown 1.6.3 是官方最终版本（仓库已归档），其 `BBDown login` 扫码登录存在"假成功"bug——只会写入 `ticket` 等无效 cookie，导致界面误报"已登录"、画质始终停留在最低档。本项目已用自研扫码流程绕开该问题。若沿用旧版 `BBDown login`，请勿再点击扫码。

登录状态按 `BBDown.data` 中是否存在 `SESSDATA` 真实校验；扫码登录进行中会忽略旧账号登录态，支持随时换账号重新登录。

### 解析视频

粘贴 BV/AV/EP/SS 链接，选择 API 模式后点击"解析"：

| API 模式 | CLI 参数 | 适用场景 |
|----------|----------|----------|
| WEB | 默认 | 普通视频 |
| TV | `--use-tv-api` | 电视端接口，部分视频画质更高 |
| APP | `--use-app-api` | 移动端接口 |

解析结果展示：视频标题、UP主、发布时间、所有分P、可用视频流和音频流。

### 下载模式

| 模式 | CLI 参数 | 说明 |
|------|----------|------|
| 视频+音频 | 默认 | 下载并混流为完整视频文件 |
| 仅视频 | `--video-only` | 仅下载视频轨道 |
| 仅音频 | `--audio-only` | 仅下载音频轨道 |
| 仅弹幕 | `--danmaku-only` | 仅下载弹幕 XML 文件 |
| 仅字幕 | `--sub-only` | 仅下载字幕文件 |
| 仅封面 | `--cover-only` | 仅下载封面图片 |

冲突规则：附加内容开关只在"视频+音频"模式生效；"仅字幕"模式固定带 `--skip-ai false`，其余模式固定带 `--skip-subtitle`，即使开关仍处于勾选状态。

### 画质与编码选择

点击视频流卡片选择目标画质和编码（HEVC/AVC），点击音频流卡片选择具体音频流，**两者都会真正生效**。

BBDown 只有视频才有画质/编码参数（`-q` 传画质、`-e` 传编码），音频没有任何参数可选。所以本项目改用 BBDown 的 `-ia`（交互式选清晰度）模式：它先把候选流打印出来，再等 stdin 里的序号。服务端在下载过程中盯住 stdout，看到"请选择一条视频流(输入序号)"就把序号写回去：

- **视频**：`-ia` 打印的列表是**按画质降序**排的，和界面上的原始顺序不一致，所以不能直接传界面下标，而是拿"画质+编码"去反查序号。
- **音频**：拿"码率+体积"反查序号。

用 `-ia` 时不再传 `-q`/`-e`，否则两者会打架。仅弹幕/仅字幕/仅封面三种模式不加 `-ia`，避免这些模式下意外的交互提示。

### 附加内容（仅"视频+音频"模式显示）

解析区下方一行三个开关，切到其他下载模式时会整行隐藏：

| 选项 | CLI 参数 | 说明 |
|------|----------|------|
| 同时下载弹幕 | `-dd` | 下载视频的同时下载弹幕 |
| 同时下载字幕(人工+AI) | `--skip-ai false` | 人工字幕（`.zh-Hans.srt`，UP 上传）与 AI 字幕（`.ai-zh.srt`）一并下载。BBDown 默认跳过 AI，取消勾选则 `--skip-subtitle` |
| 同时下载封面 | 取消则 `--skip-cover` | 下载封面图。BBDown 会把封面和字幕一起放进临时目录、混流后删掉，所以实际由主下载结束后的补跑兜底（见下） |

> 这三个开关只在"视频+音频"模式生效。切到其他模式时这一行隐藏，提交值也按模式自身的语义走，不受开关当前勾选状态影响：**仅视频 / 仅音频 / 仅弹幕 / 仅封面** 一律 `--skip-subtitle` 且 `--skip-cover`（不下字幕、不下封面、不带 `-dd`），**仅字幕** 固定 `--skip-ai false`。

### 高级设置

展开后每个选项下方都有一行小字说明，界面上直接看得懂，不必回来翻文档。

| 选项 | CLI 参数 | 说明 |
|------|----------|------|
| 跳过混流 | `--skip-mux` | 保留分离的音视频文件 |
| 音频升序 | `--audio-ascending` | 勾上就下载最小体积的音频流（实测 94 kbps → 47 kbps），同时界面上音频卡片会自动高亮到最小的那条。<br>**此开关优先于手动点选**：勾选时按最小码率选，不勾时按你点的那条 |
| 关闭多线程 | `--multi-thread false` | 单线程下载。部分 CDN 不支持多线程，报"服务器可能并不支持多线程下载"时勾选 |
| 存档记录 | `--save-archives-to-file` | 跳过已下载的视频，避免重复 |
| 文件名模板 | `-F` | 自定义单P文件名，如 `<videoTitle>` |
| 多P模板 | `-M` | 自定义多P文件名结构 |
| 语言代码 | `--language` | 指定字幕语言，如 `chi`、`jpn` |
| 分P间隔 | `--delay-per-page` | 多P下载间隔（秒），降低限流风险 |
| User-Agent | `-ua` | 自定义 UA |
| Cookie | `-c` | 手动传入 Cookie 字符串 |

字幕只有一个开关：勾选 = `--skip-ai false`（人工 + AI 全下），取消 = `--skip-subtitle`。BBDown 没有"只下人工"或"只下 AI"的开关，所以不做细分。

BBDown 的 `--video-ascending` 本项目未提供：它只在**同一画质内**挑体积最小的流，而本程序必定同时传 `-q`（画质）和 `-e`（编码），候选只剩一个，实测开关前后完全无差别，故去掉。`--audio-ascending` 则实测有效，保留。

`--allow-pcdn` 同样未提供：开关前后下载速度无明显差别，而它会引入 PCDN 节点，故去掉。

**字幕 / 封面为什么会自动补下**：BBDown 混流成功后会把整个临时目录删掉，已下载的字幕和封面（还有原始音视频流）会被连带删除——实测和音视频一起下时字幕 **6/6 全丢**，只有 `--sub-only` / `--cover-only` / `--skip-mux` 才留得住。所以主下载跑完后，服务端会对比前后有没有多出 `.srt` / 图片；没有就用 `--sub-only` / `--cover-only` 补跑（沿用同样的 `-F`/`-M`/`-p`，让文件落进同一个标题文件夹），字幕最多重试 4 次、封面 3 次。补跑过程会在状态栏显示"补下字幕 (第 N 次)..."。

BBDown 抓字幕接口本身也不稳，约五成概率返空且日志里无任何报错，所以偶尔仍会 4 次都落空，此时状态栏会提示"本次没抓到字幕"，可稍后用"仅字幕"模式重试。

补跑前会先看该视频的标题文件夹里有没有同类文件，已有就整段跳过——重复下载同一个视频时不会白跑重试，也不会误报"补下失败"。

### 分P选择

多P视频解析后可勾选目标分P，仅下载选中的分P，对应 `-p` 参数。

### 下载目录

页面顶部"下载目录"可配置下载文件存放路径，点击"选择目录"会弹出本机文件夹选择框直接选取，也可手动输入路径。保存后写入 `config.json` 持久化，下次启动仍生效，无需每次配置。路径不存在时会自动创建；留空则默认存放到本程序目录。

### 下载进度

下载时显示实时百分比、下载速度、已下载/总大小，可清晰判断大文件是在正常下载还是卡住。进度按回车符（`\r`）实时刷新，BBDown 用回车原地更新进度、无换行，因此大文件也能即时看到进展。

### 文件管理

下载完成的文件支持在线播放（视频/音频）、文本查看（`.srt`/`.ass`/`.xml`）、浏览器下载和删除操作；`.xml` 弹幕可一键导出同名 `.ass` 给 PotPlayer 等外部播放器加载，导出结果在列表里同样按"弹幕"归类。

同一视频的音视频、弹幕、字幕等文件默认归档到以视频标题命名的子文件夹中，多P视频每个分P也在其中；可在"高级设置"用自定义文件名模板覆盖。

## 文件类型标识

| 扩展名 | 类型 | 颜色 |
|--------|------|------|
| mp4/flv/mkv | 视频 | 绿色 |
| m4a/mp3 | 音频 | 蓝色 |
| srt | 字幕 | 橙色 |
| ass | 弹幕 | 灰色 |
| xml | 弹幕 | 灰色 |

`.ass` 归到弹幕一类：本项目里它只可能是"导出ASS"的产物（BBDown 的字幕一律存为 `.srt`），所以和 `.xml` 用同一套 UI（灰色标签 + 查看/下载/删除，`.xml` 额外多个"导出ASS"）。

## 技术栈

- PowerShell 5.x+ (HttpListener)
- 原生 JavaScript (SSE)
- qrcode-generator（本地 `qrcode.min.js`，前端渲染二维码）
- 零外部依赖，无需 npm/pip
